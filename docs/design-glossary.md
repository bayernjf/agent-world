# Agent World 术语对照表

> 定位：产品/设计术语的单一事实源。左侧为**标准术语**（行业通用、竞品共用、以及代码里实际使用的字段名），右侧为 **Agent World UI 术语**（产品向用户展示的游戏化用词）。
>
> 约定：**本体论是工厂，不是皮肤**——每个标准概念在工厂隐喻里都要能找到对应物。UI 一律使用右侧用词；代码、API、文档、表结构沿用左侧用词。画布节点名牌以 `Plants.tsx` 的 `KIND_LABEL` 为准，注册入口标签以 `CanvasToolbar` 为准，两处不一致时以本表「主名」为准。

---

## 一、核心实体

| 标准术语（行业 / 代码） | Agent World 术语 | 说明 |
|---|---|---|
| Graph / Flow（一张编排） | **产线** / 流水线 | 一张工作流图 |
| Node（节点） | **文坊** / 站 / 工位 | 单个加工单元；计数时用"座文坊 / 个节点" |
| Agent node | **文坊** | 加工原料的核心节点 |
| Gate node | **质检站** | 质量检验节点 |
| Source node | **原料台**（别名：投料口） | 产线起点，原料来源 |
| Sink node | **成品库 / 成品仓**（别名：出厂码头） | 产线终点，成品交付 |
| Edge（边 / 连线） | **管道** | 节点间的连接 |
| Packet（节点间传递的数据单元） | **卡车 / 在途货物** | 沿管道运输的货单，不在途传输全部货物本体 |
| Artifact（节点产出） | **产物 / 成品** | 一次加工的产出；画廊里叫"成品" |
| Skill（能力） | **技能卡 / 装备** | 文坊可装备的能力开关/配置预设，不设解锁成本 |

## 三、节点分组

| 标准术语（分组 id） | Agent World 术语 | 包含节点 |
|---|---|---|
| generation | **AI 加工** | 文坊、画坊、影坊、音坊、通用 |
| control | **车间调度** | 质检站、分拣闸、改料台、批处理站、汇流站、外包工坊 |
| data | **物料处理** | 理货台、总账房、拆包台、换装台、翻译间、识图台、代码 |

## 四、关系与连线

| 标准术语（EdgeKind 代码） | Agent World 术语 | 说明 |
|---|---|---|
| flow edge | **正向管道** | 上一步完成 → 下一步开始；"铺管道" |
| rework edge | **返工线** | 质检打回上游重做；"沿返工线退回" |
| error edge | **容错线** | 上游故障改走此线，接到兜底文坊（catch） |
| upstream / downstream | **上游 / 下游** | 前驱 / 后继节点 |

## 五、运行、调度与触发

| 标准术语（行业 / 代码） | Agent World 术语 | 说明 |
|---|---|---|
| run（一次执行） | **派发任务 / 开工** | 启动一条产线；UI 按钮"派发" |
| trigger: manual | **手动派发** | 用户手动开工 |
| trigger: cron | **定时派发** | 按 cron 自动开工（日报产线） |
| trigger: webhook | **钩子触发** | 外部 POST 自动启动 |
| trigger: event | **事件联动** | 产线完成后自动触发下游 |
| trigger: batch | **批量派发** | 一次跑 N 条输入 |
| scheduler / 调度 | **开工调度 / 车间调度** | 决定节点执行顺序与并行 |
| barrier / 汇合 | **汇合点 / 并站** | 等齐上游再触发下游 |
| worker | **工人** | 实际执行工厂的引擎实现（接真实模型） |

## 六、质量、返工与人工

| 标准术语（代码字段） | Agent World 术语 | 说明 |
|---|---|---|
| attempt | **返工次数** | 一次处理的身份；不合格打回会 +1 |
| maxAttempts | **返工次数上限** | 最多重做几次 |
| criterion（质检标准） | **质检标准** | 产出需满足的条件 |
| rework（质量驳回） | **返工 / 打回** | 质检不合格，退回上游重写 |
| retry（技术故障重试） | **重试（不用返工）** | 网络/限流等故障自动重试，与返工是两件事 |
| onExhausted: pass | **放行** | 重做耗尽仍放行 |
| onExhausted: scrap | **判废 / 报废** | 判定不合格作废 |
| onExhausted: halt | **停线（等待人工）** | 返工次数耗尽，全产线挂起等人 |
| minScore（质量分门槛） | **质量分门槛** | judge 评分低于此值直接打回 |
| minBrandCoverage | **品牌词覆盖率门槛** | 品牌词覆盖不足则打回重写 |
| halt / 人工介入 | **停线 / 质检员** | 人工审批节点或 gate 吊起等待人工 |

## 七、资源与成本

| 标准术语（代码字段） | Agent World 术语 | 说明 |
|---|---|---|
| token usage | **电费** | LLM 用量折合的耗费 |
| cost（美元） | **电费 / 成本** | 一次调用或整条线的花费 |
| budget（预算上限） | **电力预算 / 电费上限** | 超了拉闸 |

## 设计红线（对照表背后的本体论）

- **每个技术概念必须在工厂隐喻里有位置**，找不到位置的功能不做（例：KV Cache 是工人脑子里的缓存，用户不可见；向量库是档案室书架，用户只感知"能检索过去"）。
- 游戏化体现在**质感与隐喻**，不体现在人为进度阻塞：技能树不做付费墙、不设解锁成本。
- 术语只有一套来源：**UI 与产品文案用右侧列；代码、API、表结构、技术文档用左侧列。** 混用会导致产品认知漂移。
