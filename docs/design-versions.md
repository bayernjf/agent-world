## 1. P0：自动快照 + 滚动保留（资产保命层）

### 1.1 问题

用户真正的风险场景是：**改坏 → 顺手保存（graph 行被覆盖）→ 后来发现坏了 → 想回滚但没有快照**。
手动存档只在"我记得要存"时有效，恰好保护不了"我不知道我改坏了"的场景。

### 1.2 方案：保存前自动快照（pre-save snapshot）

在 graph 更新路径（`PUT /api/graphs/:id` 的保存分支）上，**写入新内容前**把当前 DB 里的旧内容
落一条自动快照：

- `note` 固定为 `auto`（UI 可区分人工/自动）；`name` 用时间戳（如 `auto-20260830-1530`）
- **节流**：同一 graph 距上次自动快照 < 10 分钟且旧内容 hash 未变则跳过（防连点保存打爆表；
  hash 用 snapshot JSON 的 sha256 前 16 位，加一列 `content_hash` 便于比对）
- **滚动保留**：每 graph 自动快照最多保留 30 条，超出按 created_at 删最旧（人工快照永不自动删）
- 保留参数（10 分钟 / 30 条）做成 settings 可调，不硬编码两处

**明确不做**：
- 不做定时快照（cron 型）——保存前快照已覆盖"每次变更可回滚"，定时只是重复
- 不改 zundo（会话内撤销与会话间快照是两层，互不替代也不耦合）

### 1.3 验收

- 保存触发自动快照；10 分钟内重复保存同内容不重复落快照
- 自动快照超过 30 条滚动删除最旧；人工快照不受影响
- 恢复人工/自动快照行为一致（走现有 restore）
- server 测试：自动快照触发/节流/滚动清理/恢复全链路（新 `graph-versions.test.ts`）

## 2. P1：恢复预览（防"盲恢复"）

### 2.1 问题

VersionPanel 恢复只有 confirm（"当前修改将被覆盖"），用户看不到要恢复的版本长什么样——
版本一多，凭名称/备注猜内容，恢复错了又得再存再恢复。

### 2.2 方案（轻量，不做 diff）

- VersionPanel 列表项加「预览」：弹层展示该快照的**结构摘要**——节点数/边数、各类型节点计数
  （复用 TemplatePreview 的 SVG 缩略图渲染，组件已通用化，传 snapshot 的 nodes/edges 即可）
- 预览只读，不提供"从预览恢复"以外的任何操作（保持面板简单）
- 不做 JSON 全文展示（信息噪音大，结构摘要 + 缩略图足够判断"是不是这版"）

### 2.3 验收

- 每个版本可预览结构摘要 + 缩略图；自动快照同样可预览
- web 测试：预览弹层渲染/关闭

## 3. P1：run 关联快照（审计层，轻量版）

> 从原 P2 提上来：不加外键也能做，成本很低，审计价值高。

### 3.1 问题

run 表只存 graph_id。用户回滚到旧版后，历史 run 记录无法回答"当时跑的是哪版图"——
排查"为什么昨天同样的产线结果不同"时缺关键上下文。

### 3.2 方案

- run 创建时，把**当时**的 graph 内容 hash（复用 §1.2 的 content_hash 计算函数）写进 run 行
  （`graph_content_hash` 列，一次 migration；不加外键、不复制全文——hash 对齐即可回答"这 run
  跑的图 = 现在的图 / = 某个快照"）
- 版本列表里给与当前 run 内容 hash 匹配的快照打「当前运行版本」标记（能对上就标，对不上不标）

### 3.3 验收

- 新 run 落 graph_content_hash；版本面板能标出"与最近一次 run 一致"的快照
- server 测试：hash 写入 + 匹配标记查询

## 4. P2 缓做决策记录

| 项 | 为什么缓做 |
|---|---|
| 两版 diff 视图（节点级高亮增删改） | 最重的 UI 投资；结构摘要 + 缩略图已解决"认出版本"的主要诉求；真正的精细对比频率低，等用户反馈再上 |
| run → graph_version 外键强关联 | 需要 run 创建路径与版本表事务耦合；hash 轻量版（§3）已回答核心审计问题 |
| A/B 测试（roadmap 提及） | ~~依赖 diff + run 关联 + 多版本并行调度~~ **已作为独立特性落地**（`ab.ts` + `/api/ab` + ABDialog/ABReport，2026-09-01 盘点确认），不属"版本管理"范畴 —— 见 [design-ab-testing.md](design-ab-testing.md) |

触发条件：出现真实的"精细对比两个版本"或"并行跑两版对比效果"的用户需求信号。
