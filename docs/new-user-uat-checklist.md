# 新用户验收清单（New User UAT Checklist）

> 用途：**新用户视角**验证产品核心功能是否可用；也是豆包后续**浏览器 E2E** 的执行清单（逐项可转 `browser-use` 指令）。
> 定位：P0 = 核心循环必验（编 → 配 → 跑 → 看 → 算）；P1 = 进阶能力抽查。
> 结果回填：每项执行后填「结果」列（✅ 通过 / ❌ 失败 / ⚠️ 部分通过或环境受限），并在「备注」写证据（截图 / 控制台 / run ID）。

## 0. 前置条件

| 项 | 本地 dev | Hasee staging |
|---|---|---|
| 入口 | `http://localhost:5173`（web）+ `:8791`（server） | `http://192.168.31.14`（nginx 同源托管） |
| server 启动 | `cd packages/server && node dist/index.js`（Node ≥ 22，建议 24） | systemd `agent-world`（无需手动） |
| 模型 key | `AGNES_API_KEY` 已配置（否则 AI 节点报 AUTH） | 已注入（注意：10 月免费额度熔断期 run 会被调度器拦截，见 handoff #41） |
| 测试账号 | 任选其一：owner / 新注册 / demo 一键体验 | 同左 |

启动校验：浏览器打开入口 → 页面可渲染、无白屏；`/api/health` 返回 `{"ok":true}`（直连 :8791 时）。

| P0-3 | 建产线 | AUTO | 新建产线：从「空白画布」或「模板库」挑一个（如 *写草稿·高频文本* / *tpl-* 系列） | 空白画布钉在最前；模板按分类分组可滚动；选择后进入编辑画布 | | |

## 3. 自动化标记约定

| 标记 | 含义 |
|---|---|
| AUTO | 豆包可全程自动执行（仅需登录态与 key） |
| SEMI | 需少量人工输入或外部依赖（如人工审批动作） |
| MANUAL | 需要人工/外部环境（如 MCP 外部客户端、付费 key） |

## 4. 建议执行顺序

1. **P0-1 → P0-8 全链走通** = 核心 MVP 成立（对齐「自托管核心完全可用」判定）
2. **P1-1 → P1-5**：编排 + 容错 + 调度（区别于普通「AI 生成器」的关键差异点）
3. **P1-6 → P1-12**：增强面，按需抽查
