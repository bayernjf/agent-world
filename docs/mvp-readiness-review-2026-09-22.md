## 1. 结论（先给判定）

| 口径 | 判定 | 一句话 |
|---|---|---|
| **A. 个人 / 小团队自托管 MVP** | ✅ **达到，且明显超出** | 核心闭环完全可用，经 **367 次真实 run + 两次断电自愈 + 3631 测试 + 安全基线 + 异地备份恢复演练**验证；BYOK 路径满足"陌生人 10 分钟接自己 provider 跑起来"。 |
| **B. 对外商业 SaaS** | ❌ **未达到** | 功能就绪，但上线门槛未过：**真实收款未闭环、无 HTTPS、模型 provider 单点无灾备、SQLite 单机无高可用、错误追踪缺真实 DSN/告警**。 |

**总评：它已经是一个功能完整、经过真实验证的自托管产品（接近 v1.0，而非玩具 Demo）；但作为对外商业 SaaS，处于"功能 Ready、上线 Not Ready"——差距集中在收款与生产运维，而不是产品功能本身。**

> 与 09-21 评审结论一致，核心判定未变：**自托管 MVP 达到且超出、商业 SaaS 未达**；以下为数据更新与变化项说明。唯一结构性变化：TTS 配音链路由"P2 阻断"转"代码就绪、卡外部 key"，商业化最后一块功能拼图补齐（仍缺收款闭环）。

## 5. 上线阻断项（按致命程度，分口径）

### 5.1 对外商业 SaaS 的硬阻断（不过这些不能对外收钱）

| 级别 | 缺口 | 影响 | 现状/依赖 |
|---|---|---|---|
| **P0** | **Stripe 真实收款未闭环（Step6）** | free 层内置模型 `tokens=0 / video=0`，新用户用平台代付模型直接 402；想升级却无法真实付款 | 代码 A0–A5 全完成且优雅降级；**卡外部输入：收款主体 + 3 个 Stripe key** |
| **P0** | **模型 provider 单点，无 fallback** | 上游一次抖动 = 全员停摆（undici 8 事故已实证 12h+，22 条 run failed） | failover 切换链路已真机打通（#44），**卡第二个 provider key** |
| **P0** | **错误追踪缺真实 DSN/告警** | 生产 bug 只能 journalctl grep，无聚合/告警 | 适配层已就绪，**差配 ERROR_REPORT_WEBHOOK_URL 或 Sentry DSN** |
| **P1** | **HTTPS/TLS + 域名** | 现内网明文 HTTP，公网不可用 | 内网自托管够用，对外必须 |
| **P1** | **长任务跨 run 续跑（G4）缺失** | 长视频在网关超时/进程重启后可能重复生成、重复计费 | G4.4 本次运行内 submit+poll 已落地，**缺跨 run 续跑** |
| **P1** | **生产数据层 SQLite 单机** | 无高可用/水平扩展 | 双驱动+迁移+Docker 演练已完成，未切 Postgres |
| **P1** | 监控告警栈未配（Uptime Kuma/Loki） | 无可用性探活告警 | `/api/health`、`/metrics`、失败告警已有，差探针与告警通道 |
| **P2** | 全链路 E2E 入 CI、压测、IaC | 规模化/合规需要 | CI 仅 2 条 Playwright 冒烟 |
| **P2** | 团队协作/RBAC/SSO、Knowledge、对象存储 | 阶段 5 范畴 | 基础 owner/admin/user 已就位 |
| **P0 过渡** | ~~`tpl-news-podcast` 缺 TTS provider~~ **代码已落地部署**，剩真机验证 | 单模板音频链路真实出片 | P1 产品化（字节计费/音色参数化/超长检测）已随 PR #378-#380 部署 Hasee c90c8d9；**卡外部：SiliconFlow/OpenAI key 做 P0 真机端到端**；另 G-C 软降级二选一待产品决策（见 [design-tts-provider.md](design-tts-provider.md)） |

### 5.2 自托管 MVP 的遗留（不阻断核心，建议排期）

1. **配第二个模型 provider / fallback**（消除单点，优先级最高——undici 8 事故的根因虽已修，但 provider 单点风险本身仍在）
2. 跨网访问则上 HTTPS（Caddy 自动证书即可）
3. 接一个最轻量错误告警（适配层已就绪，配 webhook URL 即可）
4. **观察 ②翻译新 run 完成率收敛**（当前 55%，返工环 + QC 严格 + free-tier 限流叠加；已补 intake→review flow 边，需更多 run 验证）
5. 长任务续跑 G4（若重度使用视频生成）

## 7. 建议

### 若目标 = 个人/小团队自托管正式日用（最短路径，当前已可）

- [ ] 配第二个模型 provider / fallback（消除单点，最优先）
- [ ] 跨网访问则上 HTTPS
- [ ] 配错误告警 webhook（适配层已就绪，5 分钟配置）
- [ ] 观察 ②翻译完成率收敛

### 若目标 = 对外商业 SaaS（在上面之外还要）

- [ ] **Stripe Step6**：确定收款主体，配 3 个 key，真机走通 checkout→webhook→套餐升级
- [ ] 决策 free 层是否给少量内置模型体验额度
- [ ] HTTPS + 域名 + 公网部署
- [ ] Sentry + Uptime 探针告警
- [ ] G4 长任务跨重启续跑（上线卖视频前必须）
- [ ] 切 Postgres（+ 备份/HA）
- [ ] 全链路 E2E 入 CI、压测
- [ ] 补 TTS provider 或下线 news-podcast 模板
