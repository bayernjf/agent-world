# Postmortem 模板

> 事故复盘模板（engineering-blueprint §11）。目的：**改进系统，不是追责**。始终 blameless——任何「人犯错」都要追问到「系统为什么允许人犯错」。

## 事故元信息

| 字段 | 值 |
|---|---|
| 标题 | 一句话描述 |
| 日期 | YYYY-MM-DD |
| 影响时长 | 从发现到恢复（RTO 实测） |
| 严重级别 | Sev1（服务不可用）/ Sev2（功能受损）/ Sev3（轻微） |
| 报告人 | |

## 影响

- **用户影响**：谁、多少、怎么受影响
- **数据影响**：有无数据丢失/损坏
- **财务影响**：成本损失（如误跑产线烧钱）

## 时间线（UTC+8）

| 时间 | 事件 |
|---|---|
| HH:MM | 首次发现 / 告警触发 |
| HH:MM | 定位根因 |
| HH:MM | 止血 |
| HH:MM | 恢复 |

## 根因分析

- **直接原因**：什么动作/事件直接触发了事故
- **根本原因**：五问法——连续追问「为什么」，直到找到系统层面的根因

## 修复

- **立即止血**：当时做了什么让服务恢复
- **长期修复**：如何防止同类再次发生

## 教训

- **做对了什么**：哪些流程/监控帮上了忙
- **哪里可以改进**：监控盲区、流程缺口、文档过时
